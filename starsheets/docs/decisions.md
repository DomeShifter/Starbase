# Decisions

One line per decision: what, why, what we rejected. Newest first.

| Date | Decision | Why | Rejected |
|---|---|---|---|
| 2026-11-24 | A page left open renews its single sign-on session itself: about 10 minutes before the end (`/api/info` gives `expires_in`) or when a request answers 401 with `"renew": true`, by the same `prompt=none` trip as on loading, back to the same file, only at a quiet moment (nothing unsaved or on its way, no cell being typed, no dialog, 4 s without input). An account made through single sign-on sets its first password or links another sign-in only within 10 minutes of a fresh sign-in there. People shows what the provider called someone (kept on the link, never matched on) and the provider's name | The sign-in box appeared mid-work every 12 h; renewing before the end means nothing is waiting to be saved; a stolen session mustn't be able to add a password that outlives it | Renewing in a hidden iframe (the provider's cookies are third-party there, blocked by Firefox and Safari, and the callback's cookies wouldn't be sent); carrying unsaved changes across the trip (renewing early avoids having any) |
| 2026-11-24 | Single sign-on hardening (security review of PR #4): new accounts through the provider only when STARSHEETS_OIDC_AUTO_CREATE says so, else with an allowed group, else when sign-up is on with no code; sessions made through it last 12 h, then renew at the provider without asking (`prompt=none`); linking is a POST with the current password; a new password (not changed through single sign-on) removes the link; the owner sees and removes links; the group only takes away ownership it gave; `__Host-` cookies over HTTPS; try limits count an IPv6 /64 as one address; waiting sign-ins push out the oldest instead of refusing; https:// only (http:// for localhost) | An open default ignored the owner's sign-up choice; 30-day sessions outlived removal at the provider; a GET link, kept links and unprefixed cookies let a sibling site or someone with an old password keep a way in; one /64 could fill the waiting list; linking could demote the setup owner and lock them out | Checking the provider on every request (a call per request, and the provider's own session may differ); refusing sign-ins when the list is full (lets one network block everyone) |
| 2026-11-24 | Single sign-on through the owner's own identity provider (OpenID Connect: Authelia, Authentik, Keycloak…), beside local passwords; accounts are linked by the provider's issuer and subject only, owners come only from STARSHEETS_OIDC_OWNER_GROUP (never the last owner removed), and on a new server the owner still uses the setup code unless they are in that group. `openidconnect` without its default HTTP client: ureq, no redirects, the system's certificates. Always built in (no Cargo feature) | Homelab users already run a sign-in service; linking by email or username would let anyone who can set those at the provider take over an account; one image for everyone | reqwest (30–40 more crates), the `openid` crate (reqwest only), linking by email, a Cargo feature (more code paths for little size). Still no sign-in through Google or other companies |
| 2026-11-22 | Live editing: the server holds the true copy of each open file, runs the same engine, applies everyone's changes in order and sends them on; each tab shows its own changes at once and replays them on top when someone else's arrive first | GridCraft's commands always give the same result, so replaying them is exact; formulas and inserted rows need one referee; one engine on both sides | CRDTs such as Yjs or Automerge (would mean rebuilding GridCraft's workbook); Google-style transforms (rules for every pair of hundreds of commands); a server that only passes messages on (nobody holds the truth) |
| 2026-11-22 | Accounts are local to each server (username and password, hashed with Argon2); no sign-in through Google or other companies | Owner's rule: open source and self-hosted wherever possible; works offline and on a private network | Sign in with Google / Microsoft (OIDC) |
| 2026-11-22 | People can make their own account only when the owner turns sign-up on (off by default), optionally with a sign-up code; the first account always needs the setup code from the log | A server reachable from the internet must not let strangers in by default; a small group on a home network still gets an easy way in | Open sign-up by default; invite links per person (maybe later) |
| 2026-11-22 | The file server is Rust (`crates/server`, axum), replacing server/files.py | Live editing needs the engine on the server; one language; the desktop apps can embed it later | Keeping Python next to a Rust sync service (two servers, two copies of the rules) |
| 2026-11-21 | Google-only functions live in our own crate (crates/sheets-functions), registered by a small patch | Large patches break on every upstream change; a plain values-in, values-out crate is tested on its own | Writing QUERY inside GridCraft's functions crate as a big patch |
| 2026-11-21 | Google Sheets behaviour wins over Excel where they differ; keep Excel compatibility where it costs nothing (owner's rule) | Users come from Google Sheets; .xlsx import should stay as complete as possible | Excel-first behaviour |
| 2026-11-21 | Files are plain .xlsx in one server folder with readable names; a tiny standard-library Python server (server/files.py) behind the same nginx | Files can be opened straight from the share; nothing to build or update but one script; same origin, so no CORS | A database or ids as file names (unreadable on the share); a Rust server (more to build and deploy) |
| 2026-11-21 | Sheets-only validation criteria are stored as Excel custom formulas, and drop-down item colours as conditional-formatting rules | Both survive saving to .xlsx and stay visible in the panels; no hidden StarSheets-only data | Extra fields in GridCraft's model (lost when saving .xlsx) |
| 2026-11-21 | Draw the grid 1:1 like Sheets (GridCraft draws it at 0.8) | Owner compared both side by side: cells and text looked too small | Starting at 125% zoom (the zoom box would read 125%, not 100%) |
| 2026-11-21 | Roboto is the default font (bundled, OFL) and leads the interface and sans-serif cell fonts | Owner's choice; web builds have no system fonts, so it must be bundled | Arial (Sheets' default, not openly licensed) |
| 2026-11-21 | Sheets cell behaviour is one switch (`sheets_keys`) in a GridCraft patch, not a fork of the key handling | Small diff that's easy to rebase and to offer upstream as an option | Copying GridCraft's keyboard module |
| 2026-11-21 | Toolbar icons are Material Symbols SVGs drawn through egui's SVG loader | GridCraft rebuilds its font list often, so an icon font added by us would be dropped; images are independent | Icon font; copying GridCraft's Excel-style icons |
| 2026-11-21 | Build in CI (GitHub Actions); the home server only hosts the finished site | Public repos get free CI; building ~270k lines of Rust needs more memory than the small server has | Building on a laptop; building on the server |
| 2026-11-21 | Web only | That's how it will be used; one target keeps the work small | Desktop app (GridCraft has one; we could add it later) |
| 2026-11-21 | Menus and toolbar are data tables of GridCraft command ids, checked by a test | Adding an item is one line; an upstream rename fails the test instead of a silent dead button | Hand-written UI per item |
| 2026-11-21 | Patch queue (`patches/`) applied to a pinned upstream tag; every patch is also offered upstream | Upstream changes about 40 times a day; small, named patches are easy to re-apply on each update | Forking the GridCraft repo (can't keep up); copying the crates in (loses upstream fixes) |
| 2026-11-21 | Keep GridCraft's egui UI and replace only the chrome | Grid, editing, fill, clipboard and dialogs already work; GridCraft keeps its UI layer separate from the engine | Rewriting the UI in TypeScript (months of work to reach the same grid) |
| 2026-11-21 | Name StarSheets; licence MIT OR Apache-2.0 | Owner's choice; licence matches upstream so code can move both ways | |
| 2026-11-21 | One house style (docs/house-style.md, `app/src/house.rs`): Google Sheets sizes, padding, corners and buttons, used by every dialog, menu, card and panel | Dialogs and menus had drifted, some with no padding at all; one set of helpers keeps them alike | Styling each dialog by hand (how the drift happened) |
| 2026-11-22 | With accounts, everyone has their own folder on the server (`<username>/`), and ownership follows where a file is; sharing works on files and folders (a folder share covers what is inside) | Keeps the files plain and readable on disk (they can still be opened over a file share or in Excel) while giving each person their own space, like Drive | One shared folder tree (people cannot organise their own files); Drive-style storage by id (the folder on disk would no longer make sense to people) |
| 2026-11-22 | Preview pictures are drawn on the server (top-left of the active sheet, cached per file version) | Every file gets one, also files changed outside StarSheets or never opened; cheap (a few ms) | Pictures taken in the browser (only files someone opened would have one) |
| 2026-11-22 | Where files are kept is a folder inside the folder the server is given (Docker volume), chosen in the app; changing it moves everything there and restarts the server | People can set it up without editing files; one place for everything (files, versions, accounts); a restart means nothing keeps pointing at the old place | Changing it live without a restart; letting the app reach any folder on the machine (unsafe) |
| 2026-11-22 | Copying a sheet to another spreadsheet goes through that spreadsheet's live room on the server | People who have it open see the new tab at once and nothing is overwritten | Editing the other file directly (would clash with open tabs) |
| 2026-11-23 | The sign-in box is a plain HTML form over the app, not drawn on the canvas like the other dialogs | Password managers only see real form fields; styled to match the house style | Hidden fields behind the drawn box (fragile positioning); leaving autofill unsupported |
| 2026-11-23 | Files stay .xlsx. Anything Excel cannot hold (Google-only formulas, chip colours, protection, StarSheets settings) goes into a StarSheets part inside the same .xlsx that Excel ignores; a fast-open cache (derived, disposable, keyed by file version) may be added for huge files | Files open in Excel or LibreOffice straight from the folder with no export step, nothing StarSheets needs is lost, and the engine (Excel-shaped) is the real limit, not the file | A StarSheets-only format with .xlsx export (files unreadable elsewhere, every export loses the Google-only parts, a format to maintain forever); plain .xlsx with a workaround per feature |
| 2026-11-23 | GridCraft changes move from the patch queue (`patches/`) to commits on a fork branch (DomeShifter/gridcraft `starsheets`); `upstream.pin` names the commit | 80 patches touched the same files again and again: each new one needed a hand-made base, and moving to a newer GridCraft meant re-fitting every patch. A branch rebases with normal git tools and shows the history. Rejected: copying GridCraft into this repo (17 MB, harder to offer changes back) |
| 2026-11-23 | `sheets-functions` (QUERY) moves into the GridCraft fork as one of its crates; CI runs the fork's own tests | GridCraft's `functions` crate depended on it by a path into this repo, and it on GridCraft: the fork could not be built or tested on its own. 38 GridCraft tests were failing unseen; one was a real file-fidelity bug (theme link lost on save) and one made Excel rows open 2 px too tall |
| 2026-11-23 | One input router (`app/src/input.rs`) decides each frame whether the grid gets the keys | Keys reached the cells behind button-only dialogs (Settings, merge warning, "Open link?"), and each earlier key bug was fixed in its own widget. House dialogs mark themselves, so new ones are covered; a key typed right after a dialog closes is replayed, not lost |
| 2026-11-24 | A tab says which version of the file it opened; when the server's copy is still exactly that, Welcome sends only a fingerprint, not the workbook | A big file was read and calculated twice on opening (once from the .xlsx, once from the server's JSON, 140 MB for 2 million cells). The fingerprint check keeps it safe: a mismatch reconnects and gets the workbook whole |
| 2026-11-24 | What array formulas spill is sent beside whole workbooks and sheets; tabs no longer recalculate the whole file on joining, undo or a change sent as finished state | Spilled values are calculation state that JSON leaves out; recalculating everything to get them back cost about half a second per undo on a big file |
| 2026-11-24 | The server saves on a thread of its own and holds its file lock only to write the file | Building the .xlsx of a big file took over a second, during which the file's other changes and every other request waited |
| 2026-11-24 | Big live-editing messages (64 KB and up) are sent deflate-compressed as binary WebSocket frames; message shapes stay JSON | A whole workbook shrinks about 9 times (140 → 15.5 MB for 2 million cells), which is what counts away from home; a binary serialisation (MessagePack, bincode) would save less on top and needs GridCraft's serde attributes to suit it |
| 2026-11-24 | The server also keeps documents (.docx, .odt) in the same folders; the home screen opens them in StarDocs (a separate web app served from `docs/`), and StarDocs saves through the same files API with If-Match | One place for all of a person's files with one sign-in, sharing and bin (the Starbase suite plan); documents never enter a live spreadsheet room or the sheet preview drawing |
| 2026-11-24 | Backups are built into the server: once a day, encrypted, in restic's repository format (written with rustic_core, Apache/MIT), to a folder the owner chooses; the key is kept on the server and shown to the owner to keep elsewhere; restore copies files into a new folder, never over existing ones | A home server's files need a copy on another disk without the owner setting up a separate tool. restic's format is open and widely used, so backups stay readable by restic or rustic if StarSheets is gone. Our own format was rejected for that reason, plain copies because they have no encryption or deduplication. The server grows by about 6 MB |
| 2026-11-24 | Documents' preview pictures are drawn by StarDocs (top of page 1, after each save) and sent with `PUT /api/files/ID/thumb?version=V`; the server keeps one only if V is still the file on disk, and shows it only while it is | The server can't lay out a document; refusing a picture for an older version means a slow upload never covers a newer save. Without a picture the home screen shows the StarDocs icon | Drawing documents on the server (would need a second layout engine) |
| 2026-11-24 | Cross-site protection checks the browser's `Origin` against the request's host (or STARSHEETS_PUBLIC_URL) on every request that changes something and on the live-editing connection; no custom header or JSON content type is required. The host-name allow-list is on only when STARSHEETS_PUBLIC_URL or STARSHEETS_ALLOWED_HOSTS is set | Browsers always send `Origin` on those requests, so this stops other sites without changing the apps (StarDocs sends plain same-origin fetches). A host list on by default would break home servers reached by IP or a proxy name |
| 2026-11-24 | Menu entries whose parameters depend on the active cell (Sort sheet, Freeze, Move column, Randomise range, Trim whitespace) are `panel:` ids worked out in `app/src/menuactions.rs`, which returns ordinary GridCraft commands to run | Keeps the menu table plain data and the engine untouched; tests run the same code. Randomise and Trim write values back with `range.setValues` (`parse: false`), so text stays text and formats stay in place |
| 2026-11-24 | Alternating colours, Move row up/down and Paste special › Conditional formatting only are left out for now | GridCraft bands only Excel tables (making one rewrites header cells, adds a header row when there is none and shows filter buttons), has no command to move rows, and its paste special has no conditional-formatting-only mode: each needs an engine change |
| 2026-11-24 | A removed account's folder goes into the owner's folder as "Removed – <username>", and the person is taken off every share | A new account with the same name must not inherit the old one's files or shares; moving rather than deleting keeps the files for the owner to decide about |
| 2026-11-24 | Live editing (protocol 8): the server names each connection, and a tab's own id only keeps its undo history across reconnects (together with the username); access is checked again every 30 s and after sharing changes | The tab's id was sent to everyone, so another tab could reuse it to push an editor out, edit with the editor's rights or undo their changes (security review). Carrying the right to edit in every message was rejected: a server-made name also stops the pushing out |
| 2026-11-24 | A tab's live-editing message may be 16 MB as sent and 256 MB unpacked; Resync at most every 2 s per tab; preview pictures open one file at a time | Without limits a small compressed message could unpack to gigabytes, and many preview requests at once could each unpack a file (security review). 16 MB packed is a change to about two million cells |
| 2026-11-24 | One Docker image for the suite (`ghcr.io/domeshifter/starbase`, built by the root release.yml): this server serves StarSheets at `/` and StarDocs from `SITE/docs`; `/docs` redirects to `docs/` | Both apps load their files relative to their own folder, so `/docs` without the slash would load StarSheets' files. A relative redirect still works behind a proxy that adds a path of its own. The `starsheets` image stays for StarSheets alone |
| 2026-11-24 | Starbase Drive (the home screen) and the Share dialog use Google's blue #0B57D0, not Sheets' green; the Share dialog has no ✕ (Cancel and Done close it), as in Google and Starbase Docs; Drive hides `.xlsx`/`.docx` in names (full name on hover) | Drive holds documents too, so Sheets' green made it look like part of Sheets; one share dialog look across the suite (looks review items 5, 8, 10, 19) |
| 2026-11-24 | A live file reopens, for each person, on the sheet they were last on in it (remembered in their browser per file and person: by the sheet's id, else its name, else the first sheet shown); the server saves the file open on the sheet of whoever changed it last | The server kept the sheet active when the file was first saved, so someone who added Sheet2 early saw an empty Sheet2 on every reopen and could think their work was lost. Google Sheets reopens each person where they were |
